## 1. Visão Geral do Sistema de Documentos

O sistema de configurações da Civilização de Simbiose de Âncora é composto por 100 documentos Markdown, numerados de 00 a 99, divididos em dez módulos, com 10 documentos em cada módulo. O sistema de documentos adota o SPEC.md (Normas de Geração de Documentos) como restrição rigorosa, o 00-Visão Geral do Universo de Hengyuanzhou como diretriz geral, os documentos de cada módulo se expandem detalhadamente a partir de diferentes dimensões, e finalmente os documentos de apêndice 90-99 realizam indexação, compilação e organização. Todo o sistema de documentos constitui um banco de conhecimento de configurações completo, logicamente autoconsistente, hierárquico e mutuamente referenciado.

O design do sistema de documentos segue três princípios: "modular, estruturado, expansível". Modular significa que cada documento se concentra em um tema específico e é independente e completo; estruturado significa que todos os documentos seguem normas de formato unificadas, facilitando a leitura e recuperação; expansível significa que o sistema de documentos reserva espaço suficiente para expansão, podendo melhorar continuamente as configurações por meio da revisão de documentos existentes e da adição de novos conteúdos.

## 2. Regras de Numeração de Versão

O sistema de documentos adota a regra de numeração de versão de três níveis: "número de versão principal.número de versão secundária.número de revisão":

| Nível de Versão | Regra de Numeração | Condição de Disparo | Exemplo |
|-----------------|---------------------|---------------------|---------|
| Número de versão principal | Incrementa a partir de 1 | Ajuste estrutural importante no sistema de documentos, como redivisão de módulos, alteração de configurações centrais | v1.0 → v2.0 |
| Número de versão secundária | Incrementa a partir de 0 | Revisão substancial do conteúdo central de um documento, ou adição de conteúdo de configuração importante | v1.0 → v1.1 |
| Número de revisão | Incrementa a partir de 0 | Correção de texto, ajuste de formato, unificação de terminologia e outras alterações não substanciais | v1.0 → v1.0.1 |

A versão geral do sistema de documentos atual é v1.0, ou seja, a primeira versão de lançamento completo. Cada documento registra seu próprio número de versão em seu bloco de informações do documento, e o número de versão geral do sistema de documentos é registrado de forma unificada neste documento.

## 3. Revisão das Normas de Formato de Documentos

Todos os documentos devem seguir as seguintes normas de formato unificadas (normas detalhadas consulte o SPEC.md):

### 3.1 Nomenclatura de Arquivos

O formato do nome do arquivo é `XX-título do documento.md`, onde XX é o número de dois dígitos de 00 a 99, o título está em chinês, sem espaços.

### 3.2 Estrutura do Documento

Cada documento deve conter os seguintes elementos estruturais:

1. **Título de primeiro nível**: Título do documento (consistente com o nome do arquivo)
2. **Bloco de informações do documento**: Tabela com número, módulo, palavras-chave principais (3-5)
3. **Texto principal**: Pelo menos 3 capítulos com títulos de segundo nível, usando elementos estruturados como listas e tabelas
4. **Conclusão**: Parágrafo de resumo breve
5. **Documentos relacionados**: Listar 2-3 números e nomes de documentos relacionados

### 3.3 Requisito de Contagem de Palavras

O texto principal de cada documento não deve ter menos de 800 caracteres (excluindo título e metadados).

### 3.4 Estilo de Escrita

- Estilo de documento de configurações sério e sistemático, semelhante a enciclopédia/coletânea de configurações
- Usar terminologia unificada como "Hengyuanzhou", "âncora", "simbiose"
- As novas configurações complementares devem ser logicamente autoconsistentes com as configurações existentes, em conformidade com o princípio de "baseado na realidade, atualização de leis"

## 4. Organização e Responsabilidades de Manutenção

### 4.1 Comitê de Manutenção de Configurações

O Comitê de Manutenção de Configurações é a mais alta instituição de manutenção do sistema de documentos, composta por criadores de configurações experientes, especialistas em verificação lógica e representantes de usuários. Suas responsabilidades centrais incluem:

- Aprovar a estrutura geral e os planos de revisão importantes do sistema de documentos
- Verificar alterações importantes de configurações, garantir consistência com as configurações centrais
- Arbitrar disputas de configurações, fornecer explicações autorizadas
- Organizar regularmente a autoverificação completa de consistência de configurações
- Publicar atualizações de versão geral do sistema de documentos

### 4.2 Mantenedor de Módulo

Cada módulo designa um mantenedor de módulo, responsável pela manutenção diária dos 10 documentos desse módulo. Suas responsabilidades incluem:

- Rastrear a consistência de configurações dos documentos dentro do módulo
- Verificar solicitações de revisão de documentos dentro do módulo
- Coordenar referências cruzadas entre documentos dentro do módulo
- Coletar feedback e sugestões dos usuários sobre o conteúdo do módulo
- Relatar regularmente o status de manutenção do módulo ao Comitê de Manutenção de Configurações

### 4.3 Criador de Documentos

Qualquer criador qualificado pode participar da criação e revisão de documentos. As responsabilidades do criador incluem:

- Criar ou revisar documentos seguindo as normas de formato
- Garantir que o conteúdo criado passe na verificação da tabela de autoverificação de contradições de configurações
- Anexar instruções de revisão detalhadas ao enviar a revisão
- Cooperar com o trabalho de verificação dos mantenedores e do comitê

## 5. Processo de Revisão

### 5.1 Processo de Revisão Regular

1. **Enviar solicitação**: O criador envia uma solicitação de revisão ao mantenedor do módulo, incluindo o número do documento revisado, a descrição do conteúdo revisado e o motivo da revisão.
2. **Verificação do módulo**: O mantenedor do módulo verifica o conteúdo revisado, com foco na verificação das normas de formato e da consistência dentro do módulo. Após a aprovação na verificação, envia ao Comitê de Manutenção de Configurações.
3. **Aprovação do comitê**: O Comitê de Manutenção de Configurações realiza a aprovação final do conteúdo revisado, com foco na verificação da consistência entre módulos e da consistência das configurações centrais.
4. **Executar revisão**: Após a aprovação, o mantenedor do módulo ou o criador original executa a revisão do documento.
5. **Atualizar versão**: Após a conclusão da revisão, atualiza o número de versão do documento e registra no log de atualizações deste documento.
6. **Sincronização relacionada**: Se o conteúdo revisado afetar outros documentos, os documentos relacionados devem ser revisados de forma sincronizada.

### 5.2 Processo de Revisão de Emergência

Para situações de emergência em que contradições ou erros graves de configurações são descobertos, o processo de revisão de emergência pode ser iniciado:

1. **Relatório de emergência**: O descobridor relata imediatamente o problema ao Comitê de Manutenção de Configurações.
2. **Aprovação rápida**: O comitê conclui a aprovação de emergência dentro de 24 horas e fornece o plano de revisão.
3. **Executar revisão**: Designa uma pessoa específica para executar a revisão imediatamente.
4. **Registro posterior**: Após a conclusão da revisão, complementa o registro da solicitação de revisão e da verificação.

### 5.3 Revisão Completa Regular

O Comitê de Manutenção de Configurações organiza uma revisão completa do sistema de documentos uma vez por ano, incluindo:

- Autoverificação completa de consistência de configurações
- Processamento centralizado de feedback dos usuários
- Unificação e atualização do sistema de terminologia
- Atualização sincronizada de documentos de índice
- Verificação e correção unificada do formato de documentos

## 7. Normas de Referência e Referência Cruzada de Documentos

### 7.1 Referência Interna

A referência cruzada entre documentos usa o formato "número do documento-título do documento", por exemplo, "consulte o Documento 84 'Programa Geral do Protocolo Arqueológico'". Ao fazer referência, deve-se garantir que o documento referenciado realmente exista e que o número e o título estejam corretos.

### 7.2 Referência de Terminologia

Ao usar um termo central pela primeira vez, pode-se indicar que se deve consultar o item correspondente no Documento 90 "Dicionário de Terminologia". Não é necessário repetir a indicação ao usar o mesmo termo posteriormente.

### 7.3 Referência Externa

Se for necessário referenciar materiais reais ou obras fictícias fora do sistema de configurações, deve-se indicar a fonte e explicar claramente que essa referência é um material de referência sob o princípio de "baseado na realidade", não representando a adoção completa do conteúdo pelo sistema de configurações.

## 8. Mecanismo de Garantia de Qualidade

### 8.1 Autoverificação de Contradições de Configurações

Todos os documentos recém-criados e revisados devem passar por todos os itens de verificação do Documento 97 "Tabela de Autoverificação de Contradições de Configurações", incluindo mais de 40 verificações em três categorias: consistência das configurações centrais, consistência lógica entre módulos e normas de formato de documentos.

### 8.2 Verificação Cruzada

Cada documento deve passar pela verificação cruzada de pelo menos um outro criador antes do lançamento formal, com foco na verificação da consistência lógica entre módulos e da unificação da terminologia.

### 8.3 Mecanismo de Feedback do Usuário

O sistema de documentos estabelece um canal de feedback do usuário, por meio do qual os usuários podem enviar feedback das seguintes maneiras:

- Relatar contradições de configurações e erros lógicos
- Apresentar problemas de não unificação de terminologia
- Sugerir complemento ou revisão de conteúdo específico
- Indicar erros de formato e texto

Todo o feedback é processado de forma classificada pelo mantenedor do módulo, e o feedback importante é submetido à deliberação do Comitê de Manutenção de Configurações.

### 8.4 Relatório Trimestral de Consistência

O Comitê de Manutenção de Configurações publica um "Relatório de Consistência de Configurações" a cada trimestre, cujo conteúdo inclui:

- Contradições de configurações descobertas neste trimestre e status de processamento
- Estatísticas de revisão de documentos neste trimestre
- Progresso da unificação de terminologia
- Status de processamento do feedback dos usuários
- Plano de manutenção para o próximo trimestre

## 9. Armazenamento e Distribuição de Documentos

### 9.1 Formato de Armazenamento

Todos os documentos são armazenados no formato Markdown (.md), garantindo legibilidade entre plataformas e conveniência no gerenciamento de versão. Os documentos usam codificação UTF-8, suportando chinês e caracteres especiais.

### 9.2 Estrutura de Diretórios

Os documentos são armazenados de forma unificada no diretório `anchor-docs/`, com nomes de arquivo no formato `XX-título do documento.md`. O SPEC.md, como arquivo de normas, também é armazenado no mesmo diretório.

### 9.3 Gerenciamento de Versão

Recomenda-se usar sistemas de controle de versão como o Git para gerenciar as versões dos documentos, anexando uma mensagem de commit detalhada a cada envio de revisão, registrando o conteúdo e o motivo da revisão.

### 9.4 Métodos de Distribuição

O sistema de documentos pode ser distribuído das seguintes maneiras:

- Empacotado como arquivo ZIP compactado para download
- Implantado como site estático para navegação online
- Convertido para formato PDF ou EPUB para leitura
- Importado para sistemas de gerenciamento de conhecimento para gerenciamento estruturado

## Conclusão

As Instruções de Versão e Manutenção de Documentos são a "constituição de gerenciamento" do sistema de configurações da Civilização de Simbiose de Âncora. Elas estabelecem as regras de versão, a organização de manutenção, o processo de revisão, o mecanismo de garantia de qualidade e os métodos de armazenamento e distribuição do sistema de documentos, garantindo que esse enorme sistema de configurações, composto por 100 documentos, possa sempre manter ordem e consistência no processo de crescimento contínuo. Um bom sistema de configurações não precisa apenas de conteúdo excelente, mas também de um mecanismo de manutenção perfeito para garantir seu desenvolvimento saudável a longo prazo. Este documento é precisamente o portador central desse mecanismo.
